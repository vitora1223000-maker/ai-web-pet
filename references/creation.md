# Creation and approval

The project starts with character/PET_BRIEF.json, CHARACTER_BIBLE.json and CHARACTER_LOCK.json. Fill JSON, then run views to make Markdown review copies. JSON remains authoritative. Keep approval fields pending until the user confirms that exact revision; record a dated evidence reference, not private conversation text in a public artifact.

Brief: name/type, intended website role, style/personality, colors/proportion, signature, must_keep, allowed_optimization, desired actions and input mode. Unknown values remain unknown. Record field evidence as user / observation / inference. Reuse what the user already said.

Bible: identity, visual_identity, personality, must_never_change, flexible_elements, web_readability and body_topology. For every moving part assign a stable ID and parent. Use parts/attachments, not mandatory paws/tail. Missing wings or tail is normal. Multi-limb characters have one ID per individually moving part. Keep anatomical and screen sides distinct. Record uncertain occlusion rather than hallucinating anatomy.

Lock: reference one original canonical file, hash it, preserve the approved Bible values and orientation rules. Record version and explicit approval. Subsequent identity changes require a new version and re-review of dependent actions. Do not silently relock a new image. A reference sheet may be extended without changing identity; conflicting references require review.

For the reference sheet choose only needed semantic views: front, three_quarter, side, back, detail, neutral_pose. The canonical image is authoritative; alternate views must agree. Small-size readability requires a recognizable silhouette/color/feature at real page sizes, not just a detailed full-size image.

Approval review is required by this workflow for the brief, character lock and final playback. Do not request the same approval again if existing evidence covers the exact unchanged revision.
