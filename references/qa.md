# Three separate gates

The CLI validates character approval fields and reference hashes, topology references, paths, action references, dimensions, alpha, frame IDs, durations, anchors and reduced-motion fallbacks. It does not determine whether approval evidence is truthful, whether an action is natural, or whether visual requirements are met.

Review source sheets, processed frames, complete playback, loop/exit seams, three backgrounds and actual small size. Record identity, anatomy, contact, support, continuity, attachment behavior and small-size readability in QA/REVIEW.json. Each is pass/fail/warning/not_reviewed/not_applicable with evidence. Hard failures cannot be reduced to warnings. No automatic visual reviewer is bundled.

Bind all review and acceptance records to the preview's manifest build_id. User acceptance requires watching the complete actual motion, scope and explicit evidence. Editing timing, frames, lock or player changes build identity; the previous acceptance does not transfer automatically.

Public lifecycle terms: draft, candidate, technical_pass, visual_pass_with_warnings, user_accepted, integrated, released. The helper outputs technical results and candidate builds only. It cannot issue user_accepted/integrated/released.

Test safe stop during enter and loop, repeated action changes, missing assets, reduced-motion toggle and destroy. Record browser/device coverage. File correctness and geometry are not contact, eye color or aesthetic QA.
